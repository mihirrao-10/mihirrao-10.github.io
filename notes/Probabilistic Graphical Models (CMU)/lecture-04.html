Probabilistic Graphical Models

Chapter 4: Exact Inference

Notes by Mihir Rao

We now have compact representations of joint distributions: directed and undirected graphical models. A model $M$ describes a distribution $P_M$, and the two basic things one wants to do with $P_M$ are inference — answering queries about $P_M$ — and learning — estimating $M$ from data. The two are entangled (Bayesian learning is an inference problem; learning with hidden variables is an inference problem), so getting inference right is a precondition for everything else. This chapter develops exact inference, with variable elimination as the central algorithm and message passing as the framework that generalises it.

4.1  Three Inference Queries

Most queries one cares about involve evidence: an assignment $\mathbf{e}$ of values to a subset $\mathbf{E} = \{X_{k+1}, \ldots, X_n\}$ of the variables. Three queries dominate.

Definition. Likelihood $$P(\mathbf{e}) \;=\; \sum_{x_1} \cdots \sum_{x_k} P(x_1, \ldots, x_k, \mathbf{e}).$$ The probability of the observed evidence under the model; also called the likelihood of $\mathbf{e}$.
Definition. Conditional probability (a posteriori belief) $$P(X \mid \mathbf{e}) \;=\; \frac{P(X, \mathbf{e})}{P(\mathbf{e})} \;=\; \frac{P(X, \mathbf{e})}{\sum_x P(X = x, \mathbf{e})}.$$ When the query is a subset $\mathbf{Y}$ and the remaining variables $\mathbf{Z}$ are "don't cares", we sum out $\mathbf{Z}$: $\,P(\mathbf{Y} \mid \mathbf{e}) = \sum_{\mathbf{z}} P(\mathbf{Y}, \mathbf{Z} = \mathbf{z} \mid \mathbf{e}).\,$ The summation step is called marginalisation.
Definition. Most probable assignment (MPA) $$\mathrm{MPA}(\mathbf{Y} \mid \mathbf{e}) \;=\; \arg\max_{\mathbf{y} \in \mathcal{Y}} P(\mathbf{y} \mid \mathbf{e}) \;=\; \arg\max_{\mathbf{y}} \sum_{\mathbf{z}} P(\mathbf{y}, \mathbf{z} \mid \mathbf{e}).$$ The configuration of the query variables that maximises the posterior — the maximum-a-posteriori assignment.

Three classes of applications cover most uses. Prediction: the query node is a descendant of the evidence — given a starting condition, what is the probability of an outcome? Diagnosis: the query node is an ancestor of the evidence — given the symptoms, what is the probability of the disease? Learning under partial observation: when some variables are unobserved, even point estimation of the parameters needs an inference step (the E step of EM) to impute the missing data. The directionality of information flow in a graphical model is not restricted by the directionality of the edges: probabilistic inference combines evidence from anywhere in the graph.

One cautionary note about MPA. The most likely value of a variable in isolation depends on the variables you happen to be jointly querying. A joint table with $P(y_1 = 0, y_2 = 0) = 0.35$, $P(y_1 = 0, y_2 = 1) = 0.05$, $P(y_1 = 1, y_2 = 0) = 0.30$, $P(y_1 = 1, y_2 = 1) = 0.30$ has $\mathrm{MPA}(Y_1) = 1$ marginally (since $P(Y_1 = 1) = 0.60$), but $\mathrm{MPA}(Y_1, Y_2) = (0, 0)$ jointly. The two questions are different even though they share a variable.

4.2  Complexity of Inference

Theorem. Computing $P(X = x \mid \mathbf{e})$ in a graphical model is NP-hard.

This is the worst case — a general procedure that works efficiently for every graph cannot exist. But hardness in the worst case does not mean we are stuck: for restricted families of graphs (chains, trees, polytrees, graphs of bounded tree-width) inference is polynomial. Two broad approaches make the rest of the field:

  • Exact inference algorithms. Variable elimination, the sum-product / belief-propagation message-passing algorithm, the junction tree algorithm.
  • Approximate inference techniques. Stochastic simulation and sampling methods, Markov-chain Monte Carlo, variational algorithms.

This chapter takes up the exact algorithms.

4.3  Variable Elimination: the Core Idea

The naive computation of $P(\mathbf{e})$ sums over $k^d$ joint configurations; for $d = 50$ binary variables this is hopeless. The way out is the same trick that already saved us in Chapters 2 and 3: factorisation. Sums can be pushed inside products whenever the inner factor does not depend on the summation index, and that reorganisation can collapse the cost from exponential to polynomial.

Take a hidden Markov model. The joint factors as $p(\mathbf{x}, \mathbf{y}) = p(y_1)\,p(x_1 \mid y_1)\,p(y_2 \mid y_1)\,p(x_2 \mid y_2)\,\cdots\,p(y_T \mid y_{T-1})\,p(x_T \mid y_T).$ The conditional we want is

$$p(y_i \mid x_1, \ldots, x_T) \;\propto\; \sum_{y_1} \cdots \sum_{y_{i-1}} \sum_{y_{i+1}} \cdots \sum_{y_T} p(y_1)\,p(x_1 \mid y_1)\,p(y_2 \mid y_1)\,\cdots\,p(x_T \mid y_T).$$

Computing this naively means $|\mathcal{Y}|^{T-1}$ joint configurations. But the chain structure means most factors only involve a couple of $y$'s. Pushing the inner sum $\sum_{y_T}$ past every term that does not depend on $y_T$ leaves a single sum-product that depends only on $y_{T-1}$. Pushing the next sum past everything that no longer mentions $y_{T-1}$ leaves a smaller factor depending only on $y_{T-2}$. After $T-1$ steps we have $p(y_i \mid x_{1:T})$, in $O(|\mathcal{Y}|^2 T)$ time. That trick — pulling sums inside products in a principled order — is variable elimination.

Definition. Sum-product inference task Let $\mathcal{F}$ be a set of factors (CPDs for a BN, clique potentials for an MRF) and let $\mathbf{Z}$ be a set of variables to be summed out. The sum-product task is to compute $$\tau(\mathbf{Y}) \;=\; \sum_{\mathbf{z}} \prod_{\phi \in \mathcal{F}} \phi,$$ for query variables $\mathbf{Y}$. Almost every exact inference algorithm reduces to a sequence of sum-product operations.

4.4  Variable Elimination on a General Bayesian Network

The following eight-node BN is the running example for the rest of the chapter.

Our query is $P(A \mid \tilde h)$, where $\tilde h$ is the observed value of $H$. We need to eliminate $B, C, D, E, F, G, H$. Choose the elimination order $H, G, F, E, D, C, B$. The procedure walks through eight steps, each producing an intermediate factor $m_X$ that replaces every factor that mentioned the eliminated variable $X$.

Step 1. Condition on the evidence by replacing $h$ with $\tilde h$: $m_h(e, f) = p(h = \tilde h \mid e, f).$ Factors become $P(a)P(b)P(c \mid b)P(d \mid a)P(e \mid c, d)P(f \mid a)P(g \mid e)\,m_h(e, f).$

Step 2. Eliminate $G$: $m_g(e) = \sum_g p(g \mid e) = 1.$ (Marginalising any CPD over the conditioned variable gives one.) Factors: $P(a)P(b)P(c \mid b)P(d \mid a)P(e \mid c, d)P(f \mid a)\,m_h(e, f).$

Step 3. Eliminate $F$: $m_f(e, a) = \sum_f p(f \mid a)\,m_h(e, f).$ Factors: $P(a)P(b)P(c \mid b)P(d \mid a)P(e \mid c, d)\,m_f(e, a).$

Step 4. Eliminate $E$: $m_e(a, c, d) = \sum_e p(e \mid c, d)\,m_f(e, a).$ Factors: $P(a)P(b)P(c \mid b)P(d \mid a)\,m_e(a, c, d).$

Step 5. Eliminate $D$: $m_d(a, c) = \sum_d p(d \mid a)\,m_e(a, c, d).$ Factors: $P(a)P(b)P(c \mid b)\,m_d(a, c).$

Step 6. Eliminate $C$: $m_c(a, b) = \sum_c p(c \mid b)\,m_d(a, c).$ Factors: $P(a)P(b)\,m_c(a, b).$

Step 7. Eliminate $B$: $m_b(a) = \sum_b p(b)\,m_c(a, b).$ Factors: $P(a)\,m_b(a).$

Step 8. Wrap-up. We have $p(a, \tilde h) = P(a)\,m_b(a),\,$ so $\,p(\tilde h) = \sum_a P(a)\,m_b(a),$ and the answer is

$$P(a \mid \tilde h) \;=\; \frac{P(a)\,m_b(a)}{\sum_a P(a)\,m_b(a)}.$$

Each elimination produces a new factor whose scope is exactly the variables that "co-mentioned" the eliminated one in the current factor list. The size of those intermediate factors is what controls the cost of the algorithm.

4.5  The Elimination Algorithm

Procedure Elimination ($G$, $\mathbf{E}$, $\mathbf{Z}$, $X$)
  1. Initialise. Order the variables to eliminate: $Z_1, \ldots, Z_k$. Set $\mathcal{F}$ to the full list of factors of $G$.
  2. Evidence. For each observed $E_i = \tilde e_i$, augment $\mathcal{F}$ with the evidence potential $\delta(E_i, \tilde e_i) = \mathbb{1}[E_i = \tilde e_i]$.
  3. Sum-product elimination. For $i = 1, \ldots, k$: pull from $\mathcal{F}$ the subset $\mathcal{F}'$ of factors whose scope contains $Z_i$; compute $\psi = \prod_{\phi \in \mathcal{F}'} \phi$; sum out: $\tau = \sum_{Z_i} \psi$; replace $\mathcal{F}$ with $(\mathcal{F} \setminus \mathcal{F}') \cup \{\tau\}$.
  4. Normalise. Return $\phi^*(X) / \sum_x \phi^*(X)$.

The algorithm is general — it applies to any factor graph, directed or undirected — and its only choice point is the elimination order. The order matters a great deal.

4.6  Complexity

One elimination step that computes $m_X(y_1, \ldots, y_k) = \sum_X \prod_{i = 1}^k m_i(X, \mathbf{y}_{c_i})$ requires

$$k \cdot |\mathrm{Val}(X)| \cdot \prod_i |\mathrm{Val}(\mathbf{Y}_{c_i})| \quad \text{multiplications},$$

and $|\mathrm{Val}(X)| \cdot \prod_i |\mathrm{Val}(\mathbf{Y}_{c_i})|$ additions. The work is exponential in the number of variables in the intermediate factor. Different elimination orders give different intermediate scopes, and so different total costs — sometimes by orders of magnitude.

4.7  Graph View: Moralisation and Graph Elimination

The complexity question is purely graph-theoretic. Convert the BN to its moralised undirected graph: drop directions; for every pair of nodes that share a child, add a "moral" edge between them. (The terminology dates to the introduction of these models in the 1980s; the idea is to "marry the parents".)

Now run variable elimination as a purely graph operation. To eliminate $Z$: connect every remaining neighbour of $Z$ pairwise (if they were not already), then remove $Z$ from the graph. The set $\{Z\} \cup \mathrm{neighbours}(Z)$ at the moment of removal is the elimination clique — the scope of the intermediate factor that the algebraic version of the algorithm produced at the same step. The factor $m_E(a, c, d)$ from step 4 above corresponds to the clique $\{E, A, C, D\}$, which is exactly the set of remaining neighbours of $E$ after the earlier eliminations.

4.8  Tree-Width

The overall cost of elimination is exponential in the size of the largest elimination clique. Different orderings produce different largest cliques; the smallest achievable maximum is an intrinsic property of the graph.

Definition. Tree-width The tree-width of a graph $G$ is one less than the smallest achievable cardinality of the largest elimination clique, taken over all elimination orderings.

Tree-width is $1$ for trees, $\Theta(\sqrt{n})$ for the $\sqrt{n} \times \sqrt{n}$ grid, and $n - 1$ for the complete graph. Inference is polynomial in the size of the graph whenever the tree-width is bounded by a constant, and exponential in the tree-width otherwise. Finding the elimination order that achieves the tree-width is itself NP-hard, but for many graphs that arise in practice an "obvious" near-optimal ordering can be picked by hand.

4.9  From Elimination to Message Passing

Variable elimination answers one query at a time. If we ran VE to compute $P(A \mid \tilde h)$ and then ran it again for $P(B \mid \tilde h)$, several of the intermediate factors — $m_h$, $m_g$, $m_f$, $m_e$ — could be reused; only the factors near the new query would need recomputation. The reformulation that exploits this is to think of the intermediate factors as messages exchanged between the elimination cliques arranged as a tree.

On a tree-structured GM, the right object is a clique tree (sometimes a junction tree), and the elimination operation is exactly message-passing between adjacent cliques. Computing all marginals at once takes two passes.

4.10  Message Passing on a Tree

On an undirected tree-structured pairwise MRF with node potentials $\psi(x_j)$ and edge potentials $\psi(x_i, x_j)$, the message from node $j$ to node $i$ is

$$m_{j \to i}(x_i) \;=\; \sum_{x_j} \psi(x_j)\,\psi(x_i, x_j) \prod_{k \in \mathcal{N}(j) \setminus i} m_{k \to j}(x_j),$$

where $\mathcal{N}(j)$ is the set of neighbours of $j$. The recursion says: to send the message from $j$ to $i$, first collect messages from all other neighbours of $j$, multiply in $j$'s local potentials, then sum over $j$.

For a tree, this recursion is well-defined: once a node has received messages from all neighbours but one, it can compute and send the message on the remaining edge. A leaf can send its outgoing message immediately. The recurrence terminates after $O(n)$ steps for an $n$-node tree.

4.11  The Two-Pass Protocol (Belief Propagation)

Computing every marginal takes a single round-trip across the tree. Pick any node as root. Collect: sweep messages from the leaves to the root, every node sending the message on its parent edge once it has received from all children. Distribute: sweep messages back from the root to the leaves, every node sending the outgoing message on each child edge once it has received from the parent and all other children. After both passes, every edge carries a message in both directions, and every node has all the information needed to compute its own marginal as the product of its local potentials and all incoming messages.

This is belief propagation (BP), also called the sum-product algorithm. For trees, BP is exact and runs in time linear in the number of nodes (times the cost of one sum-product step). For loopy graphs the same updates can be run, but the result is approximate and convergence is not guaranteed — this is the start of loopy belief propagation, which is taken up in the later chapter on approximate inference.

4.12  Special Case: Forward-Backward on an HMM

The HMM chain is the simplest tree, and BP on it specialises to the classical forward-backward algorithm. The forward pass computes

$$\alpha_t(y_t) \;=\; \sum_{y_{t-1}} p(y_t \mid y_{t-1})\,\alpha_{t-1}(y_{t-1})\,p(x_t \mid y_t),$$

sweeping left to right. The backward pass computes

$$\beta_t(y_t) \;=\; \sum_{y_{t+1}} p(y_{t+1} \mid y_t)\,\beta_{t+1}(y_{t+1})\,p(x_{t+1} \mid y_{t+1}),$$

sweeping right to left. Combining gives the smoothing marginal $p(y_t \mid x_{1:T}) \propto \alpha_t(y_t)\,\beta_t(y_t)$.

4.13  Beyond Trees: Junction Trees

For a GM with cycles the message-passing recurrence is no longer well-defined: a node's "remaining neighbour" set depends on what messages have already been sent, and on a cycle there is no consistent way to order them. The fix is to build a tree representation of the graph — bundle the variables into cliques such that the cliques themselves form a tree and the same variable appears only in a contiguous set of cliques — and then run message passing on that junction tree. The construction starts from the moralised, triangulated graph, identifies the maximal cliques, and arranges them in a tree satisfying the running-intersection property. We defer the full development to the next chapter; the punchline for this one is that message passing is the right framework, and junction trees are the right way to push it past the tree case.

4.14  Summary

The simple elimination algorithm captures the operation underneath every exact inference procedure: a sum over products of potentials. The arithmetic cost reduces cleanly to a graph-theoretic question — the size of the largest elimination clique, which the tree-width of the graph measures. Variable elimination on a tree turns out to be message passing along the tree edges, and the two-pass version of that algorithm — the sum-product algorithm, also known as belief propagation — computes every marginal at once. The HMM forward-backward algorithm is a special case. For loopy graphs the message-passing protocol is no longer well-defined on the graph itself, but the same idea applies to a junction tree built from the moralised, triangulated graph — the topic of the next chapter.
