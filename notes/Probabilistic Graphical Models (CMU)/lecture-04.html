Probabilistic Graphical Models

Chapter 4: Belief Propagation

Notes by Mihir Rao

Variable elimination from the previous chapter answers a single marginal query exactly, but the work it does is throwaway: ask about a different variable and the algorithm restarts from the factor set. Most of what it computes — those intermediate factors $\tau$ — does not depend on the query at all, only on local graph structure. Belief propagation (BP) is the algorithm that caches and reuses those intermediate factors. For tree-structured graphs it answers every marginal exactly after a two-pass setup. For general graphs we can run BP on a derived tree of variable clusters (the junction tree) at the cost of large clusters, or we can run BP heuristically on the original graph (loopy BP) and trade exactness for speed.

4.1  Belief Propagation on Trees

Consider a tree-structured pairwise MRF $$p(x_1, \ldots, x_n) \;=\; \frac{1}{Z}\, \prod_{i} \phi(x_i) \prod_{(i, j) \in E} \phi(x_i, x_j).$$ To compute the marginal $p(x_1)$ by variable elimination, the optimal ordering is the post-order traversal of the tree rooted at $x_1$ — eliminate leaves first, then their parents, then grandparents, and so on up to the root. Each elimination step produces an intermediate factor of the form $$\tau_k(x_k) \;=\; \sum_{x_j}\, \phi(x_k, x_j)\, \tau_j(x_j),$$ where $x_j$ is a child of $x_k$ in the rooted tree. Think of $\tau_j(x_j)$ as a message that the subtree rooted at $x_j$ sends to its parent $x_k$, summarising everything below $x_j$ that depends on $x_k$.

Now consider asking for $p(x_5)$ instead, where $x_5$ is some other node. Variable elimination re-roots the tree at $x_5$ and walks again. But the tree has not changed, and many of the messages we computed for the query at $x_1$ are identical to messages we would need for the query at $x_5$ — because between any two nodes in a tree there is exactly one path, and the messages on edges away from that path are unaffected by the choice of root. The right thing to do is compute every message once, store it, and answer any marginal query from the cache.

The number of messages is small: each edge of the tree carries exactly two messages (one in each direction), so the whole algorithm sends $2|E|$ messages, where $|E| = n - 1$ for a tree on $n$ nodes. Once all messages are stored, every marginal query is $\mathcal{O}(1)$ — just a product of the messages incident to the query node.

4.2  The Sum-Product Algorithm

The rule for what a node should send to a neighbour, and when, is short.

Definition [sum-product message]. For a pairwise tree-structured MRF, the message that node $x_i$ sends to its neighbour $x_j$ is $$m_{i \to j}(x_j) \;=\; \sum_{x_i} \phi(x_i)\, \phi(x_i, x_j) \prod_{\ell \in N(i) \setminus j} m_{\ell \to i}(x_i),$$ where $N(i)$ denotes the neighbours of $i$ in the graph. The product collects incoming messages from every neighbour of $i$ except the recipient $j$.

A node is ready to send the message to $j$ once it has received messages from every neighbour other than $j$ (a leaf is ready to send to its only neighbour immediately, because the empty product is $1$). Once every edge has carried a message in both directions, the marginals are recovered by

Definition [marginal from messages]. After all $2|E|$ sum-product messages have been computed, $$p(x_i) \;\propto\; \phi(x_i) \prod_{\ell \in N(i)} m_{\ell \to i}(x_i),$$ with the proportionality fixed by normalising over the values of $x_i$.
Algorithm — Sum-Product Belief Propagation (trees)
# input: pairwise tree MRF; output: marginals $p(x_i)$ for every $i$
initialise every message $m_{i \to j} \equiv 1$
while some node $i$ is ready to send to neighbour $j$:
  $m_{i \to j}(x_j) \leftarrow \sum_{x_i} \phi(x_i)\, \phi(x_i, x_j) \prod_{\ell \in N(i) \setminus j} m_{\ell \to i}(x_i)$
for each node $i$:
  $p(x_i) \leftarrow \mathrm{normalise}\bigl(\phi(x_i) \prod_{\ell \in N(i)} m_{\ell \to i}(x_i)\bigr)$

The relationship to variable elimination is precise: the message $m_{i \to j}$ is exactly the intermediate factor $\tau$ that variable elimination would produce if it eliminated $x_i$ as part of computing some marginal rooted on the $j$-side of the tree. BP just computes them all once.

4.3  Sum-Product on Factor Graphs

The pairwise version above generalises naturally to factor graphs, where the algorithm passes two distinct kinds of messages instead of one — variables send to factors, and factors send to variables.

Definition [factor-graph BP messages]. For a factor graph with variables $x_i$ and factors $f_s$, write $N(i)$ for the factors adjacent to variable $i$ and $N(s)$ for the variables adjacent to factor $s$. The two message types are $$ \nu_{i \to s}(x_i) \;=\; \prod_{t \in N(i) \setminus s} \mu_{t \to i}(x_i), $$ $$ \mu_{s \to i}(x_i) \;=\; \sum_{x_{N(s) \setminus i}} f_s(x_{N(s)}) \prod_{j \in N(s) \setminus i} \nu_{j \to s}(x_j). $$

A variable's message to a factor is the product of the messages it has received from its other factors; a factor's message to a variable is the marginalisation of the factor's full table, weighted by the messages it has received from its other variables. The readiness rule and the two-pass termination are the same as in the pairwise case.

4.4  Max-Product and MAP Inference

So far we have computed marginals — sums. The same algorithm computes the MAP assignment $\arg\max_x p(x)$ with a single substitution: replace every summation by a maximisation. The reason this works is that both $\sum$ and $\max$ distribute over products of non-negative factors, so the same recursive decomposition that justified sum-product also justifies max-product.

Definition [max-product message]. The max-product message from $i$ to $j$ is $$m_{i \to j}(x_j) \;=\; \max_{x_i} \phi(x_i)\, \phi(x_i, x_j) \prod_{\ell \in N(i) \setminus j} m_{\ell \to i}(x_i).$$ At termination, the value $\max_{x_i} \bigl[\phi(x_i) \prod_{\ell \in N(i)} m_{\ell \to i}(x_i)\bigr]$ is proportional to the unnormalised joint maximum $\max_x p(x)$.

To recover the maximising assignment $x^\star$, at each message-passing step record a back-pointer stating, for every value $x_j$, which $x_i$ achieved the maximum. Tracing back-pointers from any node to the leaves reconstructs the maximising configuration. On a chain MRF, max-product is the Viterbi algorithm.

4.5  Junction Trees

Belief propagation is exact for trees, but most interesting graphs have loops. The workaround is to group variables together into clusters, picked so that the clusters themselves form a tree even though the variables within a cluster may be densely interconnected. Running BP on this tree of clusters is the junction tree algorithm.

Two properties must hold for the cluster tree to give correct answers.

Definition [junction tree]. A junction tree over an undirected graph $G$ is a tree $T = (C, E_T)$ whose nodes $c \in C$ are subsets $x_c \subseteq \mathcal{X}$ of the graph's variables, satisfying:
  1. Family preservation — for each factor $\phi$ in the model, some cluster $c$ contains the scope of $\phi$: $\mathrm{Scope}(\phi) \subseteq x_c$.
  2. Running intersection property (RIP) — for every pair of clusters $c^{(i)}, c^{(j)}$, every cluster on the unique path between them in $T$ contains the intersection $x_{c^{(i)}} \cap x_{c^{(j)}}$.
The intersection $S_{ij} = x_{c^{(i)}} \cap x_{c^{(j)}}$ between adjacent clusters is the sepset on the edge $(i, j)$.

Family preservation says no factor "straddles" cluster boundaries. RIP says every variable's occurrences form a contiguous subtree — so when we eliminate a variable in one cluster, we do not accidentally drop it from a cluster elsewhere that still needs it.

4.6  The Junction Tree Algorithm

With a valid junction tree in hand, assign every factor of the original model to a cluster whose scope contains it (family preservation guarantees this is possible). For each cluster $c$, define the cluster potential $$\psi_c(x_c) \;=\; \prod_{\phi \text{ assigned to } c} \phi(x_{\mathrm{Scope}(\phi)}),$$ so that the joint distribution factors as $p(x) = \tfrac{1}{Z} \prod_c \psi_c(x_c)$.

The messages now flow over edges of the junction tree, not over edges of the original graph; their scopes are sepsets, not single variables. The update rule is essentially the sum-product rule generalised to clusters.

Definition [Shafer-Shenoy message]. The message from cluster $c^{(i)}$ to adjacent cluster $c^{(j)}$ is a function on the sepset $S_{ij}$: $$m_{i \to j}(S_{ij}) \;=\; \sum_{x_{c^{(i)}} \setminus S_{ij}} \psi_{c^{(i)}}(x_{c^{(i)}}) \prod_{\ell \in N(i) \setminus j} m_{\ell \to i}(S_{\ell i}).$$ Once every edge has carried a message in both directions, the cluster belief is $$\beta_c(x_c) \;=\; \psi_c(x_c) \prod_{\ell \in N(c)} m_{\ell \to c}(S_{\ell c}),$$ and the marginal of any variable $x \in x_c$ is recovered by summing $\beta_c$ out over the rest of the cluster.

The algorithm is the same two-pass shape as sum-product BP on trees, just at the level of clusters. Once it terminates, $\beta_c(x_c) \propto p(x_c)$ for every cluster, and any variable's marginal is one summation away.

4.7  Complexity and Constructing the Junction Tree

The cost of one message $m_{i \to j}$ is proportional to the size of the cluster potential, which is exponential in the cluster scope. The whole algorithm therefore runs in time exponential in the size of the largest cluster in the junction tree. Sending the model through one large cluster (the trivial junction tree containing every variable) is correct but pointless — it amounts to brute-force enumeration of the joint.

Finding a junction tree whose largest cluster is minimal — equivalently, computing the treewidth of the graph — is NP-hard. In practice we fall back on heuristics: any variable-elimination ordering induces a junction tree (the cliques produced during elimination become its clusters), so the min-fill, min-neighbours, and min-weight heuristics from the previous chapter all give junction trees. Models with regular structure (chains, grids, lattices) often admit hand-designed junction trees whose largest cluster is small.

4.8  Loopy Belief Propagation

When the junction tree's largest cluster is too big to handle, we can throw out exactness and just run the message-passing rules of §4.2 on the original loopy graph, ignoring the cycles. This is loopy belief propagation (LBP).

Because the graph is not a tree, the readiness rule never fires — every node always has at least one incoming message it has not yet seen. The standard remedy is to initialise every message to $1$ and then iterate the update rule repeatedly until messages stop changing.

Algorithm — Loopy Belief Propagation
# input: pairwise MRF (possibly with loops); output: approximate marginals
initialise every message $m_{i \to j}^{(0)} \equiv 1$
for $t = 0, 1, 2, \ldots$ until convergence or max iterations:
  for each directed edge $(i, j)$:
    $m_{i \to j}^{(t+1)}(x_j) \leftarrow \sum_{x_i} \phi(x_i)\, \phi(x_i, x_j) \prod_{\ell \in N(i) \setminus j} m_{\ell \to i}^{(t)}(x_i)$
for each node $i$:
  $b_i(x_i) \leftarrow \mathrm{normalise}\bigl(\phi(x_i) \prod_{j \in N(i)} m_{j \to i}(x_i)\bigr)$   # approximate marginal

Loopy BP converges to the true marginals on tree-structured graphs and on graphs with at most one cycle. On arbitrary loopy graphs it may not converge at all, and when it does converge the beliefs $b_i$ are generally not equal to the true marginals $p(x_i)$ — but in practice they are often close enough to be useful, which is why the algorithm has been widely deployed (notably in error-correcting codes, where it underlies the decoding of LDPC and turbo codes). A precise account of why it works as well as it does comes from the variational view of inference, which we will meet in a later chapter.

4.9  Summary

  • Variable elimination throws away the intermediate factors it computes. Belief propagation reuses them: a two-pass message-passing algorithm precomputes everything once and answers each marginal in $\mathcal{O}(1)$.
  • On a tree, BP is exact. The sum-product rule $$m_{i \to j}(x_j) = \sum_{x_i} \phi(x_i)\,\phi(x_i, x_j) \prod_{\ell \in N(i) \setminus j} m_{\ell \to i}(x_i)$$ delivers every marginal as $p(x_i) \propto \phi(x_i) \prod_{\ell \in N(i)} m_{\ell \to i}(x_i)$ after $2|E|$ messages.
  • The factor-graph version uses two message types — variable-to-factor ($\nu$) and factor-to-variable ($\mu$) — but obeys the same readiness rule.
  • Max-product, obtained by replacing every sum with a max, computes the MAP assignment. On a chain MRF, max-product is Viterbi.
  • For loopy graphs we run BP on a derived junction tree of variable clusters, satisfying family preservation and the running intersection property. The complexity is exponential in the largest cluster (the treewidth); finding the optimal junction tree is NP-hard.
  • Loopy BP runs the tree rules iteratively on the original loopy graph. It is approximate and may not converge, but is widely useful in practice.
